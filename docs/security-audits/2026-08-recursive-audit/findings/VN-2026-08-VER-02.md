# VN-2026-08-VER-02 — Broken staff pagination: global auth.users page != local profiles page (CONFIRMED)

**Severity:** HIGH
**Status:** OPEN
**Location:**
- `backend/app/api/routes/admin_routes.py:127-129`
- `backend/app/api/routes/supervisor_management_routes.py:181-183`
**Component:** Backend
**Category:** Functional bug with security implications (data unavailability)

## Evidence

Both `list_users` (admin_routes.py) and `list_admins` (supervisor_management_routes.py)
follow the same broken pattern:

```python
profiles_result = (
    supabase_admin.table('profiles')
    .select(...)
    .eq('facility_id', caller_fac_id)   # or .eq('role', 'admin')
    .range(start, end)                  # local pagination over profiles
    .execute()
)
profile_rows = profiles_result.data or []
profiles_by_id = {p['id']: p for p in profile_rows}

# BUG: the same page=1/limit=N is used against the GLOBAL auth.users list
auth_users = supabase_admin.auth.admin.list_users(page=page, per_page=limit)
auth_users = [au for au in auth_users if str(au.id) in profiles_by_id]
```

`supabase_admin.auth.admin.list_users(page=page, per_page=limit)` paginates the
**global** `auth.users` table across all facilities. If the local facility's
profiles happen to be on a different page of the global list (e.g., page 3 of a
50-user global list, when the local facility's 5 admins are on page 1), the
filter step discards them all.

## Risk

- **Functionality**: Staff lists disappear or appear incomplete for any facility
  once global user count exceeds `limit` (default 100). The admin UI is
  unreliable.
- **Security**: An admin who *cannot* see a user cannot manage them — but a
  malicious admin who knows the global user is on page N can craft `page=N`
  requests to enumerate users across all facilities. The
  `_get_caller_facility_id` check on the role (`'asha_worker', 'doctor'`)
  protects against the cross-tenant *write* path, but the *read* enumeration
  is unguarded.

## Recommendation

Use the *per-user* lookup primitive, which does not require global pagination:

```python
auth_users = []
for pid in profiles_by_id:
    try:
        au = supabase_admin.auth.admin.get_user_by_id(pid)
        if au: auth_users.append(au)
    except Exception: continue
```

Or denormalize the display email into the `profiles` table (the canonical
display identity), eliminating the join against `auth.users` entirely.

Add a regression test: a fresh project with 250 global users and 5 local
admins must return all 5 local admins.
