# VN-2026-08-C1-02 — CORS allowlist permits dev origins in non-development if frontend_url is unset

**Severity:** MEDIUM
**Status:** OPEN
**Location:** `backend/app/core/config.py:79-83`
**Component:** Backend (CORS / config)
**Category:** Misconfiguration

## Evidence

```python
@property
def allowed_origins(self) -> list[str]:
    origins: list[str] = []
    if self.environment == "development":
        origins.extend([
            "http://localhost:5173", "http://127.0.0.1:5173",
            "http://localhost:4173", "http://127.0.0.1:4173",
        ])
    if self.frontend_url:
        origins.append(self.frontend_url.rstrip("/"))
    if self.cors_allowed_origins:
        origins.extend(
            origin.strip().rstrip("/")
            for origin in self.cors_allowed_origins.split(",")
            if origin.strip()
        )
    return list(dict.fromkeys(origins))
```

The check `self.environment == "development"` is a hard requirement. In
practice this is correct, but:

- `Settings.environment` defaults to `"development"` if the env var is
  missing — see `Literal["development", "staging", "production"] = "development"`.
  An operator who forgets to set `ENVIRONMENT=production` in production gets
  dev origins added to the allowlist.
- There is no startup assertion that refuses to start in `environment ==
  "development"` when other production-shaped signals (e.g.
  `supabase_service_role_key` set, `data_retention_days > 0`) are present.

## Risk

- Misconfiguration can quietly widen the CORS allowlist in production.
- Combined with `allow_credentials=True` and `Authorization` header
  forwarding, an attacker on `http://localhost:5173` of a developer machine
  that *also* runs the production backend (e.g. via SSH port-forward or
  container sidecar) can make authenticated cross-site requests.

## Recommendation

- Default `environment` to a third value like `"unset"` that raises on boot,
  rather than silently defaulting to `development`.
- Add a startup check: refuse to start in `development` with a non-empty
  `data_retention_days` or non-empty `supabase_service_role_key` (i.e.
  production-shaped secrets present).
- Add a runtime warning if `allowed_origins` contains `localhost` while
  `environment != "development"`.
