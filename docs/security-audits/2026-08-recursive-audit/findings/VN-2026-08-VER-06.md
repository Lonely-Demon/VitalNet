# VN-2026-08-VER-06 — Live database has untracked `authenticated_insert` policy with no facility check (CONFIRMED CRITICAL)

**Severity:** CRITICAL
**Status:** OPEN
**Location:** `backend/supabase/schema_snapshot.sql:366`
**Component:** Supabase RLS / live database
**Category:** Direct privilege escalation / RLS gap

## Evidence

`schema_snapshot.sql:366`:
```sql
CREATE POLICY authenticated_insert ON public.case_records AS PERMISSIVE FOR INSERT TO public WITH CHECK ((submitted_by = auth.uid()));
```

This policy exists on the **live database** (per the schema snapshot), is
**not** in any tracked migration in `backend/supabase/migrations/`, and
permits any authenticated user to insert a case provided only that
`submitted_by` equals their own auth.uid().

It does **not** check:
- `facility_id` matches the caller's facility (the caller's profiles.facility_id)
- `is_active` on the caller's profile
- The caller's role is in `{asha_worker, admin}`

## Risk (chained attack)

Combined with NEW-07 (the same `schema_snapshot.sql` has the unsafe
`user_metadata` policies that phase32 was supposed to drop), an attacker
can:

1. Authenticate as any ASHA worker at PHC A.
2. Insert a case with `submitted_by = own_uid, facility_id = PHC_B_UUID,
   triage_level = 'EMERGENCY'`, vitals that trigger a real push, patient
   name of a real patient at PHC B (which they have from a separate
   chain).
3. The doctor at PHC B sees a real-looking emergency case attributed to
   a worker at PHC A.
4. The doctor is required to respond (push notification fires to PHC B's
   doctors, who believe an emergency is incoming).
5. The ASHA worker at PHC A has not done anything wrong from their
   perspective (their JWT has `role = 'authenticated'`, the policy
   allows it).

This is a clean cross-tenant case-spoofing primitive. The fix in the
original audit (VN-2026-08-C3-01) proposed adding a `WITH CHECK
(submitted_by = auth.uid())` policy. The live database has *exactly that
policy already* — and it's *too permissive* because it doesn't include
the facility check.

## Recommendation

Replace the untracked `authenticated_insert` policy with a tracked
migration that adds the proper facility-scoping:

```sql
DROP POLICY IF EXISTS authenticated_insert ON public.case_records;
DROP POLICY IF EXISTS case_records_insert_policy ON public.case_records;
CREATE POLICY case_records_insert_policy ON public.case_records
  FOR INSERT TO authenticated
  WITH CHECK (
    submitted_by = auth.uid()
    AND EXISTS (
      SELECT 1 FROM public.profiles p
      WHERE p.id = auth.uid()
        AND p.is_active = true
        AND p.role IN ('asha_worker', 'admin')
        AND (p.role = 'admin' OR p.facility_id = case_records.facility_id)
    )
  );
```

Then commit the migration to `backend/supabase/migrations/` and run
`fn_schema_fingerprint` against the live database to confirm parity.
