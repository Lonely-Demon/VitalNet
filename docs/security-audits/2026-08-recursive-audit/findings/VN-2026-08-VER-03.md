# VN-2026-08-VER-03 — Cross-facility emergency push broadcast (CONFIRMED)

**Severity:** HIGH
**Status:** OPEN
**Location:** `backend/app/api/routes/push_routes.py:77-122`
**Component:** Backend
**Category:** Mass-notification abuse / lateral effect

## Evidence

`POST /api/push/check-emergency-escalations` is gated by `require_role("admin")`
(which is a *PHC admin*, not a system-wide role). The handler then queries
`supabase_admin` for `EMERGENCY` cases globally with no `facility_id` filter:

```python
query = (
    supabase_admin.table("case_records")
    .select("id, facility_id, chief_complaint, risk_driver, created_at, last_escalated_at")
    .eq("triage_level", "EMERGENCY")
    .is_("reviewed_at", "null")
    .is_("deleted_at", "null")
    .lt("created_at", threshold)
)
candidates = query.execute().data or []
```

For each candidate, it calls `push_emergency_alert(case.get("facility_id"), ...)`
— which sends web-push to the *facility's* doctors.

## Risk (chained attack)

1. A compromised PHC admin (PHC A) calls
   `POST /api/push/check-emergency-escalations` on a loop.
2. Every call iterates over *every facility's* unreviewed EMERGENCY cases and
   re-pushes alerts to those facilities' doctors.
3. Doctors across the entire state are bombarded with duplicate push
   notifications — a "boy who cried wolf" effect that erodes response to real
   emergencies. Or worse, in a coordinated timing attack, real EMERGENCY cases
   get their legitimate escalation push buried under attacker-generated noise.
4. The audit log records the attacker (PHC A admin) — but the *effects* on other
   facilities are invisible in the audit log.

## Recommendation

This endpoint is documented as "meant to be called on a schedule by an external
scheduler" (push_routes.py:85-91). It is NOT meant for human PHC admins.

Two fixes are required:
1. **Restrict the route** to supervisor or service-role only, not PHC admin.
2. **Or**: scope the query to `caller_fac_id` for the PHC-admin case (giving
   each PHC admin an "escalate my facility" tool, separate from the global
   scheduler).

The endpoint should also be moved off the per-PHC admin surface and behind
`X-Internal-Scheduler-Token` or similar.
