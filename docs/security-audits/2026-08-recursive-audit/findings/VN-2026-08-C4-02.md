# VN-2026-08-C4-02 — `localStorage` is used for `vn_facility_phone` and other PII on a PWA

**Severity:** MEDIUM
**Status:** OPEN
**Location:** `apps/web/src/store/authStore.jsx:20,66`
**Component:** Frontend / PWA
**Category:** PII persistence on shared device

## Evidence

```jsx
// authStore.jsx
try {
  localStorage.removeItem('vn_facility_phone')
} catch { /* localStorage unavailable — nothing to clear */ }
// ...
const phone = data.facilities?.phone
if (phone) localStorage.setItem('vn_facility_phone', phone)
```

`localStorage` is *not* cleared on logout in `clearSharedDeviceState` —
the function *only* removes it; but the `setItem` happens on profile
fetch, which is also called from `onAuthStateChange` events *during* a
session.

The bigger concern: `localStorage` is accessible to any JavaScript that
runs in the origin. The Supabase tokens are in IndexedDB
(`supabase.js:34`), which is also accessible to any same-origin script
but is harder to read. The phone number is in plaintext localStorage,
which is reachable from `window.localStorage.getItem('vn_facility_phone')`
by any third-party script that lands in the bundle (a supply-chain
compromise could trivially exfiltrate it).

## Risk (chained attack)

1. A supply-chain compromise of any direct dependency (Vite, React,
   react-i18next, lucide-react) lands a script in the bundle.
2. The script reads `localStorage.getItem('vn_facility_phone')` on
   every page load.
3. Exfiltrates the PHC's phone number — useful for social-engineering
   or for SMS-spoofing attacks ("this is the PHC, we have an emergency
   referral for you").

The phone number is not the most sensitive field on the system, but it
*is* a key in a chain: combined with the `EmergencySmsAlert` flow (which
sends an SMS from the worker's device to that number), an attacker who
can write to `vn_facility_phone` can redirect the SMS to a
phone-controlled-by-them — a true exfiltration / diversion attack.

## Recommendation

- Move `vn_facility_phone` to sessionStorage (cleared on tab close) or
  to in-memory React state, accepting the offline-loss trade-off (the
  EmergencySmsAlert already requires user gesture; the user can also
  type the phone number).
- Or: keep it in IndexedDB under a separate store, with the same
  shared-device teardown contract as `form-drafts`.
- Add a `Content-Security-Policy` header that prevents third-party
  scripts from running (`script-src 'self'` only), closing the
  exfiltration vector.
