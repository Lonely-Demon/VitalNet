# VN-2026-08-C9-01 — `get_client_ip` trusts `X-Forwarded-For` without enumerating trusted proxies; an attacker can spoof their IP in the audit log

**Severity:** MEDIUM
**Status:** OPEN
**Location:** `backend/app/core/audit.py:120-130`
**Component:** Backend / Audit
**Category:** Audit log integrity / IP spoofing

## Evidence

```python
def get_client_ip(request: Request) -> str:
    """Extract the client IP, preferring proxy headers (Railway/most PaaS sit behind a proxy)."""
    forwarded = request.headers.get("x-forwarded-for")
    if forwarded:
        return forwarded.split(",")[0].strip()
    real_ip = request.headers.get("x-real-ip")
    if real_ip:
        return real_ip
    if request.client:
        return request.client.host
    return "unknown"
```

The `X-Forwarded-For` header is the *first* IP in the list, which the
caller controls. There is no validation that the request actually
arrived via a trusted proxy. An attacker on a direct connection (or
behind an unrelated proxy) can send `X-Forwarded-For: 1.2.3.4` and
have that IP logged as their source.

## Risk (chained attack)

1. Attacker performs a PHI exfiltration (e.g., via a chain built on
   the outbox `owner_id` gap or the auth-context `app_metadata.role`
   confusion).
2. The audit log records the attacker's spoofed IP.
3. Forensic investigation finds `1.2.3.4` is a residential IP in
   Karnataka, India — but the actual attacker is in a different
   jurisdiction.
4. The forensic trail is broken; law enforcement / compliance review
   follows the wrong lead.

The `X-Real-IP` header has the same issue.

## Recommendation

1. Use `uvicorn --proxy-headers` and configure `trusted_hosts` /
   `forwarded_allow_ips` to enumerate only the actual proxy IPs.
2. Or, use Starlette's `ProxyHeadersMiddleware` with a strict
   `trusted_hosts` list.
3. Or, in `get_client_ip`, fall back to `request.client.host` *unless*
   the request's source IP is in a known set of trusted proxy IPs.
4. Add a CI test that asserts an attacker-supplied `X-Forwarded-For`
   does *not* change the logged IP when the request comes from
   outside the trusted proxy set.
