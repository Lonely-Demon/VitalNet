# VN-2026-08-C6-01 — Pediatric heart-rate threshold of 170 bpm fires the "extreme tachycardia" override for normal infants

**Severity:** HIGH (clinical-safety)
**Status:** OPEN
**Location:** `packages/clinical-core/src/rules/rules.ts:89-95`
**Component:** clinical-core rules engine
**Category:** Pediatric safety / mis-triage

## Evidence

```ts
if (hr !== null && (hr < 35 || hr > 170)) {
  return {
    id: "extreme_hr",
    citation: "Extreme bradycardia/tachycardia outside any physiologically stable range at any age",
    detail: `Extreme heart rate (${hr} bpm)`,
  };
}
```

The citation claims "outside any physiologically stable range at any age."
This is clinically false. Normal heart rate ranges:

| Age            | Normal HR (bpm) | Upper limit of normal |
|----------------|------------------|------------------------|
| 0–3 months     | 100–160          | 180 (crying/feeding)   |
| 3–12 months    | 100–150          | 170                    |
| 1–3 years      | 80–130           | 150                    |
| 3–5 years      | 70–120           | 140                    |
| 5–12 years     | 60–110           | 130                    |
| Adult          | 60–100           | 100 (resting) / 200 (exertion) |

The "extreme HR" override (HR > 170) is supposed to flag an *adult*
emergency. For a 6-month-old infant, 170 bpm is normal sinus rhythm. A
3-year-old crying can hit 170. Yet the rule fires EMERGENCY for any
patient with HR > 170, regardless of age.

For HR < 35: that's a more universal lower bound (athletes can go to
30, but it's unusual), so it's defensible for adults. For infants, the
5th percentile HR is ~100 — HR < 35 is a code.

## Risk (chained attack / clinical safety)

1. ASHA worker submits a 4-year-old with fever (which legitimately
   causes HR 140-160) and includes anxiety/crying artifact. Recorded HR
   reads 175 from a cheap pulse oximeter.
2. The override fires EMERGENCY based on HR > 170.
3. The doctor sees an EMERGENCY case, the system pushes emergency
   notifications, the ASHA worker calls an ambulance.
4. Real consequence: unnecessary escalation, family panic, transport
   costs, and *reduced* trust in the system for future real emergencies.
5. The reverse (false negatives) is worse: the override *also* doesn't
   fire for a 2-month-old at HR 220 (SVT), because the override is
   bounded above by 170+ and would fire there — so this particular
   failure mode is "false positive at 171, also false positive at 220."
   The right behaviour: age-banded HR thresholds.

This is a real pediatric patient-safety issue. It also means the
overall the rules engine is **adult-only in practice**, despite the
schema accepting `patient_age` as a real field.

The `engine.ts::qsofaScore(bpSys, symptoms.has("altered_consciousness"), age)`
and `news2LikeScore(age, ...)` do take age into account, but the
*override* layer in `rules.ts` does not.

## Recommendation

Make every override in `rules.ts` age-aware:

```ts
function extremeHrThresholds(age: number): { low: number; high: number } {
  if (age < 0.25) return { low: 50, high: 220 };  // < 3 months
  if (age < 1)    return { low: 50, high: 200 };  // 3-12 mo
  if (age < 3)    return { low: 50, high: 180 };  // 1-3 yr
  if (age < 5)    return { low: 50, high: 170 };  // 3-5 yr
  if (age < 12)   return { low: 45, high: 160 };  // 5-12 yr
  if (age < 18)   return { low: 40, high: 150 };  // 12-18 yr
  return { low: 35, high: 170 };                  // adult
}
```

Apply the same logic to SpO2, BP, and temperature overrides (a 4-year-old
at 39.0C is febrile, not in "concerning NEWS2 territory" the way an
adult is).

Add a vitest case for every age band with a known normal-reading
patient that the override does *not* fire.
