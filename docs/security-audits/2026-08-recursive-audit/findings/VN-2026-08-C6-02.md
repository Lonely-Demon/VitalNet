# VN-2026-08-C6-02 — `checkOverrides` short-circuits on the first critical symptom; an attacker who controls the symptoms array can hide a missing second red-flag by ordering

**Severity:** LOW (clinical-safety)
**Status:** OPEN
**Location:** `packages/clinical-core/src/rules/rules.ts:60-69`
**Component:** clinical-core
**Category:** Determinism / safety property

## Evidence

```ts
const hits = [...symptoms].filter((s) => CRITICAL_SYMPTOMS_OVERRIDE.has(s as Symptom));
if (hits.length) {
  return { id: "critical_symptom_override", ... };
}
```

`CRITICAL_SYMPTOMS_OVERRIDE` contains 4 symptoms: `altered_consciousness`,
`seizure`, `severe_bleeding`, `swelling_face_throat`. If *any* are
present, the function returns immediately with that one rule. This is
correctly a "first match wins" decision (the function returns a single
FiredRule), and the engine wraps it in `[override]` so only one rule is
reported. The triage tier is `EMERGENCY` regardless of which one fired,
so the *tier* is correct.

But the *firedRules audit log* only records one of multiple
potentially-applicable rules. The `firedRules` array in the engine
output is meant for clinical post-hoc review and analytics — a doctor
looking back at a case should see "this was EMERGENCY because of
seizure AND severe bleeding." The current code records only one.

The schema enforces `MAX_SYMPTOMS = 20`, so a malicious caller can
submit all 4 critical symptoms and the audit trail records only the
first one matched. There's no security exposure (the tier is correct)
but the analytics/auditability is degraded.

## Risk

- Audit log incomplete: a "what made this case EMERGENCY" question
  can't be answered from the recorded `firedRules`.
- Affects the ML model agreement analytics: the advisory model sees
  multiple critical symptoms, the rules engine records one, the
  `modelAgreed` signal is partially noisy.

## Recommendation

Return *all* applicable rules, not just the first:

```ts
export function checkOverrides(form: OverrideInput): FiredRule[] {
  const symptoms = new Set(form.symptoms);
  const rules: FiredRule[] = [];
  // ... each check pushes to rules instead of returning early
  return rules;
}
```

The engine's "first match wins" can be replaced with "tier is EMERGENCY
if any rules fired; record all."
