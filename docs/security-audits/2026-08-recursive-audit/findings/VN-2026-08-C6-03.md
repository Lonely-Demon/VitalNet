# VN-2026-08-C6-03 — `triage.ts::runModel` uses `probabilities[classIndex]` but `evaluateTrees` may return NaN for unseen features; NaN < threshold comparisons are false, silently mis-classifying

**Severity:** MEDIUM (clinical-safety + correctness)
**Status:** OPEN
**Location:** `packages/clinical-core/src/triage.ts:64-72`, `packages/clinical-core/src/treeEvaluator.ts`
**Component:** clinical-core / ML
**Category:** Silent misclassification

## Evidence

```ts
function runModel(form: TriageFormInput, trees: TreeJson, featureNames: readonly string[]): ModelOpinion {
  const featureMap = buildFeatureMap(form);
  const vector = orderFeatureVector(featureMap, featureNames);
  const { classIndex, probabilities } = evaluateTrees(trees, vector);
  const tier = TRIAGE_LABELS[classIndex] ?? "ROUTINE";
  const confidence = probabilities[classIndex] ?? 0;
  const sorted = [...probabilities].sort((a, b) => b - a);
  const margin = sorted.length > 1 ? sorted[0]! - sorted[1]! : 1;
  const lowConfidence = confidence < LOW_CONFIDENCE_PROBA || margin < LOW_CONFIDENCE_MARGIN;
```

The decision tree evaluator (`treeEvaluator.ts`) walks each tree with the
feature vector. For categorical features, unseen values may map to a
default branch. For numeric features, NaN may propagate if the input is
`null` and the tree's threshold comparison returns NaN.

`NaN < 0.55` evaluates to `false`, so `lowConfidence` becomes `false`
even though the model's output is meaningless. `NaN < 0.15` is also
`false`, so the `margin < LOW_CONFIDENCE_MARGIN` check is also
defeated.

The advisory model returns `lowConfidence: false` with a meaningless
`confidence` value, the rules-first engine's tier is correct, but the
*audit log* records a confident ML opinion that disagrees with the
rules — leading to spurious `modelAgreed: false` flags in analytics.

## Risk (chained attack)

1. A caller submits a form with several missing vitals (e.g., a rural
   PHC with a broken pulse oximeter).
2. The feature vector contains many `null`s, which propagate to NaN in
   the tree evaluation.
3. The advisory model returns a high-confidence tier that doesn't
   actually reflect the data.
4. The doctor's UI may show "ML disagrees" or `needs_review` from
   `modelAgreed: false`, but the *actual cause* is missing data, not
   clinical uncertainty.
5. The ML agreement analytics (used as a model-promotion gate per
   DECISIONS §33) is polluted with non-clinical false disagreements.

## Recommendation

- In `evaluateTrees`, replace any NaN with 0 (or document the default)
  and add an explicit `unseen: true` flag to the result.
- In `runModel`, set `lowConfidence = true` if *any* feature is null
  (when the model is configured to expect all features).
- Add a vitest test: `evaluateTrees` with all-NaN features returns
  `lowConfidence: true`.
