## 1. Executive Summary & Problem Statement

Across VitalNet's completed public-data external evaluation cycle (CDC NHAMCS Gate 1B, Korean KTAS Gate 3A) and the 16-arm synthetic ASHA input-contract ablation study, an acute, systematic safety failure mode was empirically established:

> **Core Safety Failure Mode**: **Severe Emergency Under-Triage under Missing Clinical Context**.
> When encounters lack structured symptoms, free-text chief complaints, or complete physiological observations, the frozen production triage inference engine defaults toward lower-acuity classifications (`URGENT` or `ROUTINE`), under-triaging true emergency presentations at unacceptable rates in evaluated cohorts.

This document establishes the formal specification for the **Synthetic Safety-Remediation Candidate Study** (`tools/training/study_safety_remediation.py`). This study implements a controlled, reproducible, research-only simulation harness to evaluate candidate missing-context handling, four-state symptom screening distinctions, and deterministic human-escalation pathways entirely outside the production runtime.

## 2. Strict Operational Boundaries: Research Simulation vs. Production Runtime

To preserve system safety, auditability, and regulatory boundaries:

1. **Production System Immutability (Frozen Baseline)**:
   - The production classifier (`backend/app/ml/models/triage_classifier.pkl`), browser-side decision trees (`apps/web/public/models/triage_trees.json`), feature configurations (`features_config.json`), deterministic safety rules (`packages/clinical-core/src/rules/**`), backend API routes, and database schemas remain **100% frozen and unmodified**.
   - Zero retraining, parameter tuning, weight adjustment, threshold modification, or runtime code changes are performed in this candidate study.

2. **Synthetic-First / Non-Production Execution**:
   - The study executes exclusively on deterministic synthetic cohorts generated under fixed random seeds (`--seed 42`).
   - Zero loading, inspection, transformation, scoring, or inference is performed on real datasets (NHAMCS, KTAS, Iran ED, MIMIC).
   - All proposed operational states (`INSUFFICIENT_INFORMATION_FOR_CDS`, `INDETERMINATE`) and escalation reason codes are research outputs generated by the evaluation harness; they are **not active runtime behaviors of the current production application**.

## 3. Four-State Symptom Context Distinction

A critical vulnerability identified during evaluation audits is that permissive input schemas treat an omitted or blank symptom list as equivalent to an explicit negative declaration. The candidate study strictly models four distinct symptom screening states:

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                        FOUR-STATE SYMPTOM SCREENING TAXONOMY                           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 1. positive_symptom                                                                    │
│    • Definition: One or more allow-listed danger signs were actively reported.         │
│    • Policy: Evaluated via standard triage engine with deterministic safety rules.     │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 2. explicit_negative_screen                                                            │
│    • Definition: Operator actively screened danger signs and confirmed NONE present   │
│      (simulated via `no_acute_danger_signs_declared = True`).                          │
│    • Policy: Explicit negative evidence; allows standard 3-tier triage if vitals ok.  │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 3. unknown_or_not_asked                                                                │
│    • Definition: Symptom checklist was omitted, bypassed, or not collected.           │
│    • Policy: Absence of evidence != evidence of absence. Triggers INSUFFICIENT_INFO.  │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ 4. declined_or_unavailable                                                             │
│    • Definition: Patient was unable or unwilling to answer (distress, unconscious).    │
│    • Policy: Explicit missing context. Triggers INSUFFICIENT_INFORMATION_FOR_CDS.      │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Non-Equivalence Invariant**:
> A blank symptom list (`symptoms: []`) or empty chief complaint must **NEVER** be interpreted as an explicit negative screen. Unless an active declaration (`no_acute_danger_signs_declared: True`) is recorded, empty symptoms are treated as missing context (`unknown_or_not_asked` or `declined_or_unavailable`), prohibiting silent low-acuity classification.

## 5. Candidate Policy Precedence Hierarchy (`candidate_remediation_v1`)

The candidate remediation policy evaluates encounters according to the following strict precedence hierarchy outside the production runtime:

```
                          [Patient Intake Encounter]
                                      │
                                      ▼
                        [1. Demographic Completeness]
                       (patient_age, patient_sex present?)
                                      │
                    No ───────► [INSUFFICIENT_INFO] (severe_missingness)
                                      │ Yes
                                      ▼
                        [2. Vital Signs Completeness]
                       (>=2 missing canonical vitals?)
                                      │
                    Yes ──────► [INSUFFICIENT_INFO] (severe_missingness)
                                      │ No (0 or 1 missing)
                                      ▼
                     [3. Critical Single Vital Check]
                     (Exactly 1 missing SpO2 or SBP?)
                                      │
                    Yes ──────► [INSUFFICIENT_INFO] (critical_vital_unmeasured)
                                      │ No (0 missing, or exactly 1 missing temp/HR/DBP)
                                      ▼
                      [4. Symptom Screening Context]
              (positive_symptom OR explicit_negative_screen?)
                                      │
                    No ───────► [INSUFFICIENT_INFO]
                                (missing_symptom_confirmation_with_extreme_vitals
                                 if extreme vitals present; else missing_symptom_confirmation)
                                      │ Yes
                                      ▼
                    [5. Deterministic Safety Net & NEWS2]
                 (Extreme vital derangement or critical symptom?)
                                      │
                    Yes ──────► [EMERGENCY Override / URGENT Floor]
                                      │ No
                                      ▼
                      [6. Statistical Classifier & Rules]
                      (Rule floor > Statistical ML Tier?)
                                      │
                    Yes ──────► [Apply Floor] (rule_model_disagreement)
                                      │ No
                                      ▼
                        [Standard Assigned Tier (3-Tier)]
```

### 5.1 Vital-Completeness Boundary Specification
- **$\ge 2$ missing canonical vitals**: Triggers non-triage escalation with reason `severe_missingness`.
- **Exactly 1 missing SpO2 or SBP**: Triggers non-triage escalation with reason `critical_vital_unmeasured` due to the critical diagnostic sensitivity of oxygenation and perfusion.
- **Exactly 1 missing temperature, heart rate, or DBP**: Does not trigger immediate vital-sparsity escalation; proceeds to the symptom-state gate (and allows ordinary triage if symptoms are positively reported or explicitly screened negative).
- *This vital-completeness boundary is an exploratory research candidate policy, not an established clinical rule.*

### 5.2 Preservation of Severe Vital Signals During Escalation
When an encounter exhibits missing/unknown symptom context alongside extreme observed vitals (e.g. $\text{SpO}_2 \le 85\%$, $\text{SBP} < 70$, $\text{HR} < 35$ or $> 170$, $\text{Temp} < 33.0^\circ\text{C}$ or $> 41.5^\circ\text{C}$):
- The policy routes the encounter to non-triage escalation (`INSUFFICIENT_INFORMATION_FOR_CDS`) with reason code `missing_symptom_confirmation_with_extreme_vitals` and sets `extreme_vital_present: True`.
- Severe physiological danger signals are **never silently discarded** or collapsed into unflagged missing-symptom states.
- *This escalation behavior is a research simulation design choice and is not presented as a clinically accepted workflow.*

## 6. Non-Triage Scoring Separation & Safety Metrics

To maintain rigorous statistical and clinical separation:

### 6.1 Non-Triage Operational States
- `INSUFFICIENT_INFORMATION_FOR_CDS` and `INDETERMINATE` are non-triage operational states, **NOT clinical tiers**.
- Standard $3 \times 3$ confusion matrices (`ROUTINE`, `URGENT`, `EMERGENCY`) are strictly computed on encounters receiving an ordinary clinical tier.
- Escalated/indeterminate cases are reported separately:
  - `tiered_case_count` & `tiered_case_rate`
  - `indeterminate_count` & `indeterminate_rate`
  - `extreme_vitals_flagged_during_escalation`: Number of escalated encounters exhibiting extreme vital derangement.
  - `escalation_reason_counts`: Breakdown across `missing_symptom_confirmation`, `missing_symptom_confirmation_with_extreme_vitals`, `critical_vital_unmeasured`, `severe_missingness`, `rule_model_disagreement`.
  - `reference_tier_distribution_among_escalated`: Ground-truth distribution of escalated cases.
  - `total_reference_emergencies`, `tiered_reference_emergencies`, and `emergency_cases_escalated`.

### 6.2 Primary Ordinary 3-Tier Metrics (Among Tiered Cases)
1. **EMERGENCY Sensitivity (Tiered Cases)**: Exact Wilson 95% score confidence intervals computed on tiered reference emergencies.
2. **EMERGENCY Miss Count & Miss Rate**: Proportion of tiered reference emergencies under-triaged (excluding escalated emergencies).
3. **Critical Two-Tier Drop Rate (`EMERGENCY` $\to$ `ROUTINE`)**: Catastrophic under-triage rate among tiered reference emergencies.
4. **Overall Under-Triage & Over-Triage Rates**: Encounters where predicted tier diverges from reference tier among tiered cases.
5. **Denominator Integrity**: `total_reference_emergencies = tiered_reference_emergencies + emergency_cases_escalated`.

### 6.3 Combined Operational Diagnostic
- **Emergency Retention or Escalation Rate**:
  $$\text{Operational Coverage} = \frac{\text{Tiered EMERGENCY Predictions} + \text{Escalated True EMERGENCY Encounters}}{\text{Total Reference EMERGENCY Encounters}}$$
  *Strictly designated as an exploratory operational pipeline diagnostic; never to be interpreted as emergency sensitivity, clinical efficacy, or clinical safety.*

### 6.4 Calibration Engineering Diagnostics (Pre-Registered Grid)
- Proportion of tiered predictions falling below confidence thresholds $\max P(\text{tier}) \in \{0.50, 0.60, 0.70, 0.80\}$.
- Prediction entropy distributions (mean and standard deviation).
- *Strictly an exploratory engineering diagnostic for technical calibration review; not a clinical acceptance criterion.*

## 8. Explicit Limitations & Clinical Non-Claims

1. **No Clinical Validation Claim**: This candidate study is an investigational simulation and does not constitute clinical validation or medical safety certification.
2. **No Regulatory Clearance**: VitalNet has not received Software as a Medical Device (SaMD) clearance from CDSCO, US FDA, or CE mark.
3. **No Autonomous Triage**: The candidate architecture is strictly an advisory clinical decision-support tool. All clinical triage decisions require licensed human healthcare professionals.
4. **Synthetic Domain Bounds**: Synthetic distributions approximate physiological relationships but cannot substitute for prospective clinical trials in rural Indian primary health centres.
